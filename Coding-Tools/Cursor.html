    # Cursor

    Cursor 是一个基于 AI 的新一代编程工具，它能够帮助开发者更快速、更智能地编写代码。

    # 主要特点

    1. AI 代码补全
    2. 智能代码生成
    3. 自然语言交互
    4. 代码解释和重构
    5. 多语言支持

    # 问答模式 Chat 和 Composer

    • Chat 类似 ChatGPT 聊天框，模式性质是你问它答
    • Composer 会根据当前聊天快速生成与修改现有代码，无需我们离开工作流，模式性质是你发出指令，它给出答复并执行指令

    # Composer 具有 normal 和 agent 两种模式

    normal 和 agent 根据复杂度进行选择，这种模式都可以检索代码库和文档，正常创建和写入文件，不过 agent 模式的 Composer 可以自动提取相关上下文、运行终端命令、按语义去搜索代码，执行一些文件操作，属于一个更高级的操作。

    • normal 适用于复杂度低的情况
    • agent 适用于复杂度高的情况

    # @ 唤起功能菜单

    在 Chat 或 Composer 对话框中通过 @ 唤起功能菜单，文件或文件夹也可以通过拖拽的方式

    • @Files 选用文件，通过 @Files 唤起文件列表，然后选中目标文件
    • @Folders 选用文件夹，通过 @Folders 唤起文件夹列表，然后选中目标文件夹
    • @Code 选用代码块，通过 @Code 唤起代码块列表，然后选中目标代码块
    • @Docs 选用文档，通过@Docs 唤起文档列表(文档可以是 Cursor 默认第三方文档，也可以是自定义文档)，然后选中目标文档；Cursor 会自动抓取链接中的内容并将其编入索引，选中文档后会将文档内容纳入上下文
    • @ 后面跟对应的链接，然后选择 Add link 然后可以对该链接进行问答

    • @Web 搜索网络上的内容，Cursor 会根据使用者提供的信息和上下文，构建搜索查询，搜索网络，查找相关信息作为上下文回复，相当于一个AI搜索引擎的能力
    • @Git 选择历史 Git 提交，可以查看修改的内容，也可以对比几次提交的差异(diff)
    • @Notepad 可以当临时笔记记录，可以充当项目相关的一些上下文记录，也可以保存一些AI的对话历史记录，由于 Chat 和 Composer 两种模式的上下文是不互通的，Notepad 可以作为解决两种模式上下文关联的解，以下是创建 Notepad 的入口

    • @Codebase 会采集代码中重要的文件或代码块，Cursor 会根据给出的指令，对采集的上下文进行排序，然后推理，最后给出最匹配的答复；总的来说使用 Codebase 时 Cursor 会做4件事：
      1. 收集：Cursor 会扫描整个项目，检查到与指令相关的文件或者代码块；
      2. 重新排序：Cursor 会根据查询的相关性对上下文进行排序，即收集到的文件或代码块跟指令越相关，排序越靠前；
      3. 推理：Cursor 会思考如何利用上下文；
      4. 生成：给出回复

    Codebase indexing 背后的逻辑：

    将本地项目代码库分割成一小块一小块的语言数据，然后将每个小块发送到 Cursor 服务器上，Cursor 会使用 OpenAI 的 Embedding API 进行嵌入，然后把这些文件的相对路径也一起存到远程的矢量数据库中，这样就可以利用索引，来提高答复的质量

    Cursor 尊重 .gitignore，Cursor 在索引前会检查项目根目录 .gitignore 文件，.gitignore 文件中声明的文件或目录是不会被索引的，如果没有 .gitignore 并且想缩小索引的范围，可以项目根目录下创建 .cursorignore 文件来添加需要忽略的文件或目录，哪些文件应该不被索引呢？例如：日志文件、环境变量文件、构建输出的文件、缓存文件、第三方配置文件等

    # 添加自定义文档

    例如将项目中的接口文档链接、需求文档链接或者是任意一个在线文档连接录入进 Docs，这样在进行文档时通过 @docs 选中对应的文档，就可以让 Cursor 根据文档生成内容，这种方式类似一个项目的私有AI知识库

    通过 Cursor 的Settings->Features 找到 Docs，添加文档链接，https://www.cursor.com 与 https://www.cursor.com/ 是不一样的，如果是前者，Cursor 只会索引这一个文档链接的内容，如果是后者(带 /)，Cursor 除了索引这一个文档链接的内容之外，还会索引这个文档链接下的所有子页面和子目录。

    # Cursor 乱改问题

    担心 Cursor 乱改我们的代码怎么办，将问题拆解开来有三点：

    1. 预防，如何让 Cursor AI 按照我们的想法生成并修改代码，简单来说就是“如何向AI提问”

    思考：某些词汇的表达让AI产生了误解

    解决：

    - 让 AI 复述需求指令，迅速确认 AI 是否精准理解了我们的需求
- 明确需求辐射范围，尽可能让需求指令小，足够单一化，不要让 AI 猜我们要做什么，要有足够针对性并明确指令范围
- 需求拆解，如果需求指令不方便细粒度到足够小一个一个单元的去提问，需要把需求一条一条写清晰
	- 把 AI 当成小孩子，在沟通时，我们应该尽可能的逻辑清晰，描述问题时要加以引导
    1. 检测，Composer 一次可以帮我们修改很多文件的代码，如何确认这些修改是我们想要的

    可以对单个文件进行查看、应用、放弃，也可以对所有文件全部应用(Accept all)或全部取消(Reject all)，保存所有(Save all)可以先看修改后的一个效果，如果符合可以全部应用(Accept all)，不符合可以全部取消(Reject all)

    1. 回滚，如果出现AI乱改了代码，或者想恢复到之前的一个问答版本，可以进行回滚处理(restore)；Cursor 会给每个 Composer 的问答做一个 Checkpoint 标记
